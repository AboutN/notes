## UV的基本用法

| 核心任务 | 常用 UV 命令 | 功能简述 |
| :--- | :--- | :--- |
| **项目初始化** | `uv init [项目名]` | 创建新项目目录，生成 `pyproject.toml` 等基础文件。 |
| **虚拟环境管理** | `uv venv` | 创建虚拟环境（通常在首次 `uv sync` 时自动完成）。 |
| **依赖安装与同步** | `uv add [包名]` & `uv sync` | `uv add` 将包添加到依赖并更新 `pyproject.toml`，`uv sync` 根据该文件安装所有依赖并创建锁文件。 |
| **运行项目/脚本** | `uv run [命令]` | 在项目虚拟环境中执行命令，无需手动激活环境。 |
| **安装命令行工具** | `uvx [包名]` | 在临时隔离环境中运行Python工具（如 `uvx black`），避免全局安装。 |

### 💡 核心用法详解

#### 项目初始化与环境搭建
使用 `uv init` 是开始一个新项目最快捷的方式。它会为你生成一个标准的项目结构，包括核心的 `pyproject.toml` 配置文件。之后，运行 `uv sync` 命令，UV 会自动执行一系列操作：创建虚拟环境（默认在 `.venv` 目录）、解析 `pyproject.toml` 中的依赖、生成确保依赖版本一致的 `uv.lock` 锁文件，并将所有依赖安装到虚拟环境中。

#### 依赖管理
- **添加依赖**：使用 `uv add` 命令，例如 `uv add requests fastapi`，同时安装多个包时, 包名之间用空格隔开 。这会自动将包添加到 `pyproject.toml` 的 `dependencies` 列表中，并更新 `uv.lock` 文件。你可以通过 `--group dev` 参数（如 `uv add --group dev pytest`）将包标记为开发依赖。
- **依赖同步与清理**：`uv sync` 是保证环境一致性的关键命令。它确保当前虚拟环境内的包与 `pyproject.toml` 和 `uv.lock` 文件完全一致，会自动安装缺少的包并卸载未在配置中声明的包。与 `pip` 不同，当使用 `uv remove` 卸载一个包时，UV 能够智能地识别并移除那些不再被任何包所需的依赖，保持环境的清洁。

#### 运行与工具
- **在环境中运行**：`uv run` 命令非常方便，你无需手动激活虚拟环境。例如，要启动一个 FastAPI 应用，可以直接运行 `uv run uvicorn main:app --reload`，UV 会自动确保命令在正确的项目上下文中执行。
- **临时运行工具**：`uvx`（是 `uv tool run` 的别名）非常适合运行像代码格式化工具 `black`、`pytest` 或 `httpie` 这样的命令行工具。它会在一个临时的隔离环境中下载并运行该工具，运行完毕后清理，不会污染你的项目或全局环境。

### 💎 把现有的项目迁移到UV
对于全新的个人项目，强烈推荐直接使用 UV 来享受其性能和一体化带来的便利。对于现有的、正在使用 `pip` 和 `requirements.txt` 的项目，UV 也能很好地兼容，先通过 `uv venv` 创建虚拟环境, 然后通过下面的方式安装依赖项:
- 通过 `uv pip install -r requirements.txt` 。
- 通过 `uv add -r requirements.txt` 将依赖添加到 pyproject.toml，然后再执行 uv sync
